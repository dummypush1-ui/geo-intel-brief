B5 supplied BRICS parsed-feed preparation only. Default OFF; no application
builder imports or mounts it. Flag OFF returns before input/file reads. ON needs
explicit bounded plain source/outcome snapshots, selected RSS tiers, categories,
dedupe threshold and a caller-supplied UTC observation timestamp. This timestamp
is declared fixture evidence, never a checked-live assertion. Outcomes keyed by
source index keep duplicate source names separate. Disabled sources remain
visible. Original legacy name-keyed status collapses duplicate names; B5 does
not reproduce that loss. Status counts are parsed entries before truncation,
filtering or storage, not new articles. Partial errors remain distinct from empty
success; warning entries are used. No all-sources-healthy inference is made.

Preserves source order, first30 entries per feed, regex HTML strip, summary500,
raw published/updated strings, dedupe then category then BRICS relevance. No
publication date coercion, date cutoff, Geo score, credibility or risk policy.
Malformed empty-title/URL entries are refused by existing processing boundary,
not silently deleted. Bounded source/outcome exact fields refuse custom objects.
Source pins cover original RSS/official/classification/dedupe and safe processing.
No original config, dotenv, launcher, collector/store or alert module imported.

No live HTTP, fallback URL fetch, XML repair/parser or source terms proof. Those
are future transport work, not a claim of this parsed-entry unit. Official mode
is disposition only: original tier3 code is a homepage success stub, never real
article extraction. B5 does not manufacture that stub as news. It lists held
scrape source indexes, including disabled ones, matching original official's
lack of enabled check without fetching them. No arbitrary callback/writer.
No store, clock, IDs, collected time, alerts, delivery or schedule effects.
No public-source health API changed. Real mapping/read-only privacy gates remain
held for B3. A future collector writer needs its own write/job authority and
ledger, separate BRICS identity, replay/uncertain-write handling and explicit
critical-alert/delivery separation. Geo native201 must not be relabeled BRICS.
