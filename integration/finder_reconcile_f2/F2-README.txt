F2: supplied Finder snapshot reconciliation connected to isolated real rebuild

Default OFF: MERGED_FINDER_RECONCILE_PREP_ENABLED=false. Exact true also
requires MERGED_FINDER_REFRESH_PREP_ENABLED=true. OFF returns before snapshot,
source-file, Git or build reads. No new public route, active workflow or CLI.

This unit closes the data reconciliation gap between a supplied original Finder
snapshot and F1's actual catalogue rebuild. It does not fetch official feeds,
run old updaters, send secrets, use AI, publish data or make legal conclusions.
Original current repository target: push2006/finder-hsn-codee. A supplied revision
is a provenance label, NOT independently authenticated proof in this module.
Each supplied file must match its full UTF-8 SHA256; source acquisition and
revision-to-bytes verification remain a separate connection unit.

Only src/tradepartners.ts and src/sanctions.ts are accepted. The closed envelope
must say supplied_public_snapshot_not_official_proof, contain that exact repo,
a full lowercase 40-character revision and exactly two unique path/content/hash
rows. Each file <=32MiB. No arbitrary file paths or executable source selection.
Partner data is parsed without eval/VM/import. Only fixed type declaration,
6-digit codes, closed fields, top-five named partner arrays, positive safe
integer amounts, known quantity units and boolean estimate flags are accepted.
Trade year rollover holds. JSON/duplicate/reserved-key and syntax boundaries
reject executable tails and malformed snapshots. Individual partner lines are
bounded to64KiB; at most10000 codes. Sanctions accepts only the original closed
three-line declaration, bounded 200000 triples and OFAC/EU/UFLPA source labels.

Last-good policy:
- Existing partner records remain exact as data, including records missing
  from the snapshot. New codes may enter an UNVERIFIED scratch candidate.
  Changed existing records and missing codes are listed for separate review.
- Every prior sanctions row remains, including duplicate baseline rows. New
  unique triples may enter the scratch candidate. Zero removals are applied;
  snapshot disappearance is never official delisting proof. Report includes
  count and SHA256 of the exact addition/retained-missing delta. Original
  success/freshness labels are not advanced. Legal screening remains not ready.
- No additions means no cosmetic source rewrite. Additions are supplied to F1
  in memory, rebuilt in F1's disposable scratch, syntax/identity checked, and
  returned held for snapshot AND consumer review. Nothing replaces repo/live
  data; no pins, provider calls, credentials, issue/PR or publish permission.
- Scratch partner header explicitly says unverified mixed candidate, not a
  current-source refresh. Report remains not_officially_verified throughout.
