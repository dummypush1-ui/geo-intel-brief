F11 - optional data-only PDF reports for selected public Finder snapshots

Default OFF: PUBLIC_FINDER_DATA_REPORT_ENABLED=false.
Requires an exact, already-reviewed F8 binding and F9 composition enabled.
No deployment activation, source acquisition, data refresh, new credential,
provider connection, BRICS collection or paid action is included.

The source/F8 safe-render bytes are not edited or repinned. F11 transforms a
verified safe-render copy with closed seams; F9 verifies derivation again.
Data scripts remain exact. All 21 report sections, source data, client controls
and static calculations remain present. The report button opens without a key,
and report generation never calls aiAvailable or tplNarrative. Even a direct
renderer call discards a supplied narrative. Existing manual public-AI bridge
composition remains on the ordinary noncached F9 route when configured; its
service stays held. It is not a report data source or a provider activation.

F10 caches only the exact F11-derived safe render, not the noncached bridge or
later branding composition. Its full render digest gives it a separate URL,
worker scope and cache from an old edition/profile. Save/Clear stay explicit.
Old caches are not silently rewritten, deleted or upgraded.

Report copy distinguishes preserved dataset claims from current verification.
The section count follows TPL_SECTIONS. Product cross-links and duty rows use
their actual lengths; SYS.length describes only the total systems in the data.
No row is invented to reach 22. General fallback context remains labeled, with
no prompt to enter a key or promise of live AI. Date labels describe the source
snapshot, not a verified refresh schedule.

Printing resets viewport min-heights for shortlist output. The data report
uses natural print flow instead of one hard page break per section. Print
contents and usage notes share the cover; body tables still repeat headers.
Existing print listeners, popup recovery, data tables and sections are kept.

Tests:
  python -B -m unittest tests.test_finder_report_f11
  python -B tests/browser_finder_report_f11.py /tmp/f11-output
  RUN_FINDER_F11_BROWSER=1 python -B -m unittest tests.test_finder_report_f11

The browser regression can instead accept OUTPUT ARCHIVE SHA256 ROOT for a
real held source. It runs actual loopback Chrome at 390 and 1100px, HS and IN
coffee fixtures, actual UI buttons, popup-block recovery, PDF page/text and
pixel-density checks, contact sheets and network/storage assertions. It uses
no user browser profile or external service. The fixed fixture page counts are
not a general page-count guarantee for all products. Review PDF pixels before
acceptance; test export success alone is insufficient.
